# 📎 Codex 個人站設計流程

## 摘要

> 這篇文章把「用 Codex 做有設計感網站」拆成可執行流程：先找參考、提煉 DESIGN.md、確認設計語言，再開始寫程式。重點不是讓 Codex 自由發揮，而是把審美、限制、素材與迭代方式先講清楚。

## 重點

- 用 Codex 做 UI 時，核心是先說清楚「想要什麼樣」，而不是立刻寫程式。
- `DESIGN.md` 可把頁面目標、讀者、參考、顏色、字體、首屏、卡片、動效與禁忌拆成規則。
- 參考來源可分成現成設計風格、真實網站設計規則、靈感圖庫與動效元件。
- taste-skill 可協助去除常見 AI 味，依情境選用 `design-taste-frontend`、`image-to-code` 或圖片生成技能。
- 生成後應開本地頁面對照 DESIGN.md 檢查，再逐項修正首屏、色彩、字體、卡片與素材。

## 可行動事項

- [ ] 建立一份個人站 `DESIGN.md` 範本，要求 Codex 先產出設計說明、等待確認，再進入實作與瀏覽器檢查。

## 原文整理

原文主張，非設計背景的人若想用 Codex 做出有質感的個人站，不應直接下「幫我做一個高級感個人網站」這種模糊指令。這類提示很容易得到深色背景、紫藍漸層、功能卡與 AI 標籤堆疊的制式頁面。

更穩的方式是先要求 Codex 暫停寫程式，整理一份普通人能讀懂的 `DESIGN.md`。這份文件不需要像專業設計規格書，但要能把抽象的「感覺」拆成可執行規則。

### DESIGN.md 應該包含什麼

原文建議讓 Codex 先寫清楚：

- 頁面要表達什麼。
- 目標讀者是誰。
- 參考裡要學什麼。
- 參考裡不要學什麼。
- 顏色與字體的大致方向。
- 首屏如何安排。
- 按鈕、卡片與圖片怎麼處理。
- 動效要做到什麼程度。
- 哪些常見 AI 味不要出現。

可使用的提示方向是：先不要寫程式，請根據需求和參考整理 `DESIGN.md`，並在寫完後停下來等使用者確認。

### 先找參考，不要讓 Codex 猜

原文把參考分成三類。

第一類是可直接使用的風格參考，例如 Refero Styles。這類資源不只提供截圖，也可能提供現成的 `DESIGN.md`、顏色、字體與樣式規則。適合已經知道自己想要極簡、復古、暗色、雜誌感或實驗排版等方向時使用。

第二類是從喜歡的真實網站中提取設計規則。原文提到 `web-to-design-md`，可將網頁裡的顏色、字體、按鈕、間距與卡片樣式整理成 Codex 能讀的文件。使用時要刪除對方 logo、文案、圖片和品牌元素，只借鑑風格，不複製完整結構或素材。

第三類是在還沒有明確方向時，先逛參考庫。原文提到 Mobbin、Page Flows 可看真實產品流程，Recent、Collect UI、Minimal Gallery、Land-book、Lapa Ninja 可找審美方向，React Bits 與 GSAP skills 可參考動效與元件感。

### 找到參考後的流程

原文建議固定走三步：

1. 讓 Codex 根據參考和需求生成 `DESIGN.md`，具體寫出頁面氣質、顏色、字體、首屏布局、按鈕、卡片、圖片、動效與不要做什麼。
2. 使用者先確認 `DESIGN.md`，尤其檢查頁面表達、主要參考、顏色、禁忌與動效是否明確。
3. 確認後才讓 Codex 按 `DESIGN.md` 實作頁面，並要求桌面與行動端適配，完成後啟動本地服務並在瀏覽器檢查。

### taste-skill 的角色

原文將 taste-skill 視為一組改善 AI 網頁審美、參考圖還原與視覺生成的 skills。簡化選擇方式如下：

| 需求 | 建議 skill |
| --- | --- |
| 普通網頁想去 AI 味 | `design-taste-frontend` |
| 有參考圖想做成網頁 | `image-to-code` |
| 沒參考圖想先出網頁效果圖 | `imagegen-frontend-web` |
| 做手機 App 頁面 | `imagegen-frontend-mobile` |
| 做品牌視覺板 | `brandkit` |
| 改造已有專案 | `redesign-existing-projects` |
| 做極簡風格 | `minimalist-ui` |
| 做更強視覺與動效 | `gpt-taste` 或 `high-end-visual-design` |

原文的簡化判斷是：有參考圖就用 `image-to-code`；沒有參考圖就先用 `imagegen-frontend-web`；普通網頁想去 AI 味就用 `design-taste-frontend`。

### 生成後如何修改

如果第一次生成結果不滿意，原文不建議只說「不好看，重新做」。更有效的方式是讓 Codex 啟動本地服務，在瀏覽器裡打開頁面，對照 `DESIGN.md` 和截圖列出最明顯的問題，再逐項修改。

檢查重點包括：

- 首屏是否有表達。
- 顏色是否跑偏。
- 字體層級是否太弱。
- 卡片是否太模板。
- 圖片和素材是否像占位圖。
- 行動端是否有溢出。

若問題在素材，而不是 CSS，可先用內建圖片生成能力補足主視覺、頭像、封面或專案展示圖，再要求 Codex 替換進頁面並調整尺寸、裁切與留白。

### Cowart 畫布二次修改

原文也建議將參考網站截圖、目前頁面截圖與生成素材放進 Cowart 無限畫布一起比較。使用者可以圈出不滿意處並寫下注釋，再讓 AI 按標註修改素材或頁面。這種流程適合處理難以用文字描述的「感覺不對」問題。

### 原文結論

Codex 做 UI 的正確打開方式，不是讓它自由發揮，而是先把參考、審美和表達目標整理成 `DESIGN.md`。沒有參考就先找參考，素材不足就先生成素材，生成圖不對就放到 Cowart 裡對比和標註。這樣 Codex 更像是一個能一起打磨頁面的協作者。
