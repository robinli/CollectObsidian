# Obsidian Codex 個人知識庫

## 摘要

> 這篇文章提出一套輕量的 AI 第二大腦流程：用 Obsidian 承接網頁剪藏、靈感與筆記，再讓 Codex 負責整理、歸檔、關聯與復盤。它的重點不是建立更複雜的資料夾，而是把低摩擦收集與 AI 反饋結合成可持續的知識閉環。

## 重點

- 許多知識庫失效，是因為只圍繞「輸入、分類、保存」設計，缺少輸出、回訪與行動。
- 文章把傳統知識庫描述為「人工輸入、人工分類、人工復盤」，而 Codex 第二大腦則補上整理、關聯與提示。
- 建議用 Obsidian 當本地資料載體，用 Codex 桌面版作為智能整理與思考層。
- 原文建議新知識庫可先用 `Inbox`、`Notes`、`Ideas`、`Projects` 四個資料夾，並用 `AGENTS.md` 說明個人背景、目標、專案與整理規則。
- Web Clipper 讓網頁素材先進 Inbox，再由 Codex 批次整理，比追求完全自動化更容易落地。
- 每日簡報與每週深度復盤，是讓知識庫主動產生回饋的關鍵環節。

## 原文整理

### 核心問題：知識庫常變成檔案倉庫

原文指出，很多人一開始使用 Obsidian、Notion 或其他筆記工具時，會熱衷於建立資料夾、分類、標籤、收藏文章與保存摘抄。但一段時間後，系統往往只剩下「整理得很漂亮的資料堆」。

問題不一定是使用者不努力，而是多數知識庫只處理輸入：如何收集、歸檔、保存。真正產生價值的是輸出：能否被檢索、產生關聯、輔助決策，並推動下一次行動。

### 傳統知識庫與 Codex 第二大腦的差異

原文將傳統知識庫流程概括為：

> 人工輸入 -> 人工分類 -> 人工打標籤 -> 人工復盤 -> 很少回訪 -> 逐漸遺忘

這種模式的風險是所有關鍵動作都依賴人主動完成，一旦忙碌、懶散或遺忘，系統就會停擺。

文章理想中的 Codex 第二大腦流程則是：

> 全網內容低摩擦流入 -> Codex 自動整理歸檔 -> Codex 挖掘關聯 -> Codex 每日推送簡報 -> Codex 每週深度復盤迭代

它的價值不是只幫忙存筆記，而是讓知識庫形成雙向回饋：使用者負責輸入生活、學習、靈感與問題，Codex 負責整理、連接、復盤與提醒。

### 工具組合：Obsidian + Codex

原文建議只準備兩個工具：

- Obsidian App：作為本地知識庫載體。
- Codex 桌面版 App：作為智能整理與思考層，透過圖形化介面操作。

文章強調這套方案不需要部署伺服器，也不需要複雜自動化配置，主要透過聊天指令讓 Codex 協助處理。

### 極簡倉庫結構

原文示範的第二大腦使用四個固定資料夾：

- `Inbox`：所有新內容、靈感、文章與素材的統一入口。
- `Notes`：已整理的文章、閱讀高亮、學習資料與外部知識。
- `Ideas`：個人的原創想法、感悟、思考與復盤。
- `Projects`：正在推進的工作、副業、學習計畫與目標任務。

另外，文章建議在根目錄建立 `AGENTS.md`，把它視為 Codex 理解個人知識庫的「人格說明書」。內容可包含個人身份、年度目標、當前專案、困惑問題、資料夾用途，以及希望 Codex 執行的工作方式。

### Web Clipper：降低收集成本

文章對比 Readwise、N8N 等較重的自動化方案，建議普通使用者可以先採用更簡單的做法：

- 白天看到好內容，只用 Obsidian Web Clipper 保存。
- 不急著分類、打標籤或改檔名。
- 晚上交給 Codex 統一整理、歸檔、復盤與提煉靈感。

原文建議將 Web Clipper 的預設保存位置設為 `Inbox`，並把命名規則設為日期加標題，讓後續整理更容易。

### 夜間整理、每日簡報與每週復盤

原文建議每天晚上讓 Codex 批次消化 Inbox，處理素材屬性辨識、歸檔、Markdown 格式整理、來源保留、筆記關聯挖掘與每日復盤。

每日簡報的目標是讓知識庫不只等待搜尋，而能主動提醒最近輸入內容之間的隱藏關係、思考模式與值得追問的問題。

每週復盤則聚焦於較高層次的認知迭代，包括：

- 本週逐漸形成但尚未明確總結的核心觀點。
- 新舊認知之間的矛盾與衝突。
- 知識體系中的缺口與盲區。
- 下一步最值得落地的一件事。

### 長期價值

文章把這套系統的成長分成三個階段：

- 1 個月：減少遺忘，讓文章、靈感、摘抄與學習資料進入統一系統。
- 3 個月：開始出現跨時間連接，重新喚醒過去想法。
- 6 個月：形成個人智庫，記錄認知迭代、觀點變化、專案推進與思考習慣。

核心結論是：第二大腦的價值不在於更複雜的資料夾系統，而在於能不能持續把資訊轉化為思考回饋。
